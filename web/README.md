# HSK AI 中文陪练 · MVP v0.4

两个模式：
- **一句话纠错**：中文学习者写完一句话，不知道说得对不对、怎样更自然
- **场景对话**：AI 扮演场景里的另一个人，你说的话决定对话能不能往下走

基于微信小程序「HSK 海岛」升级而来的网页版产品，用于求职作品集（AI 产品运营 / 教育科技方向）。

---

## 一、这个版本解决什么

### 1.1 一句话纠错

**用户问题**：中文学习者写完一句话，不知道表达是否正确、怎样说得更自然。现有工具要么没有反馈，要么反馈太多看不懂。

**最小功能**：输入一句中文 → AI 输出「主要问题 / 更自然的表达 / 解释 / 小提示」四段式反馈。

### 1.2 场景对话

**为什么要加这个**：一句话纠错解决的是正确性问题，但它没有让人打开第二次的理由——
纠错本质上是自上而下的批改，没有人喜欢被批改。

**做法**：AI 扮演场景里的另一个人。你说的话决定对话能不能往下走：

```
学习者：我少糖要一杯奶茶
店  员：啊？您是要少糖的奶茶吗？        ← 角色表现出真实反应
        ┌─────────────────────────┐
        │ 语序反了                  │  ← 纠错此时才出现
        │ 中文里「少糖」放在后面      │
        │ 建议：我要一杯奶茶，少糖     │
        └─────────────────────────┘
学习者：我要一杯奶茶，少糖
店  员：好的，大杯还是中杯？            ← 对话推进
```

心理链条反过来了：**纠错不再是审判，是通关要用的工具。**

### 1.3 随机开局：四张牌 + AI 导演（v0.4 新增）

v0.3 的剧本是写死的——5 个场景、固定台词，玩两遍就腻了。v0.4 把它改成**每局随机生成**：

| 牌 | 数量 | 作用 |
|---|---|---|
| 场景 | 18 个（日常 / 办事 / 社交 三类） | 决定你要办成什么事 |
| 对手性格 | 10 种 | 急性子、高冷、话痨、健忘、推销狂、傲娇…决定对方怎么跟你说话 |
| 本局挑战 | 9 种 | 加在你身上的约束：只能说礼貌用语、身上只有 20 块、每句至少 10 个字 |
| 意外事件 | 14 种 | 在第 2 或第 3 轮突然插入：手机没电、有人插队、对方听错了、价格突然变了 |

组合数 **45,360 种**。点「🎲 换一批」重抽。

**剧本不再是我写的，是 AI 现场编的。**开局时把「场景 + 性格 + 挑战 + 意外」交给模型，
它返回：一句开场白、4 轮任务（每轮含给判断用的 `goal` 和给学习者看的 `tip`）、
以及意外发生时角色当场说出口的那句话。

```
同一个场景再玩一次，台词也不一样。
```

AI 返回的剧本要过 `validateScript()` 校验（opening 非空、steps 正好 4 项、每项 goal/tip 齐全、
twistLine 非空）。**校验不过或请求失败就回落到本地模板**，并在页面上写明「本局剧本来自本地模板」——
不让用户以为自己玩到的是 AI 编的，实际是兜底内容。

**意外怎么接**：意外触发后，角色那句话会进对话上下文，并且明确传给判断模型：
> 「只是重复原来的话不算化解，得能应对这个麻烦。」

一次说清就化解的，成绩卡上写「一次化解」；绕了几圈才过去的写「绕了几圈才过去」。

### 1.4 成绩卡

用 canvas 画一张 660×1100 的图，含：完成轮数、没说清几次、看提示几次、用时、
**本局挑战、意外事件及是否化解**、本次评价、「你说得最顺的一句」。

**所有数字都来自本次真实操作，不做任何修饰。**卡片底部直接写明这一句。
评价规则是公开的：`retry=0 且 peek=0` 才是「一遍过」，用过提示就说用过。

**刻意不做**：语音识别、真实语音对话、课程体系、用户系统、登录注册。先把点做透测透。

## 二、怎么用

1. 双击 `start.bat`（会自动启动本地服务器并打开浏览器）
2. 在「模型服务」里选服务商（或自定义中转站），填 **Base URL / 模型名 / API Key**
3. 点「测试连接」确认通了 → 点「保存配置」
4. 选等级 → 输入句子 → 点「检查这句话」
5. 切到「场景」页 → 选类别 → 不满意就点「🎲 换一批」→ 开始对话（AI 会先编剧本，等一两秒）
6. 通关后下载成绩卡 → 点「再玩一个场景」继续
7. 切到「测试案例」页 → 批量运行 20 条 → 逐条人工核对 → 导出 CSV

> 必须用 `start.bat` 启动，不能直接双击 `index.html`。
> 浏览器对 `file://` 页面的跨域请求限制更严格，本地服务器可避开。

## 三、模型服务可自由切换

支持**任意 OpenAI 兼容接口**：官方直连、国内中转站、自建网关（One API / New API）、本地 Ollama，全部能填。
只要它提供 `/chat/completions`，就能用。

内置预设（`providers.js`）：

| 服务商 | Base URL | 默认模型 |
|---|---|---|
| DeepSeek 官方 | `https://api.deepseek.com` | `deepseek-v4-flash` |
| 硅基流动 SiliconFlow | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` |
| OpenRouter | `https://openrouter.ai/api/v1` | `deepseek/deepseek-chat` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 阿里通义千问（兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` |
| 自定义 / 中转站 | 自己填 | 自己填 |

> 各家地址以官方文档为准，有变动直接在输入框里改。

### 三个兼容性设计

1. **Base URL 自动补全**：只需填到域名或 `/v1`，程序自动拼成完整的 `/chat/completions`。
   输入时下方实时显示拼好的地址，方便核对。
2. **严格 JSON 模式可关，且会自动降级**：部分中转站不支持 `response_format: json_object`。
   勾选时会先带参数请求，若报错信息显示不支持，自动去掉该参数重试一次。
3. **一键测试连接**：发一个 `max_tokens: 1` 的最小请求，直接返回延迟、HTTP 状态、
   以及**实际命中的模型名**——中转站常做模型映射，这个字段能验证你填的名字对不对。

## 四、关于 API Key（重要）

**Key 不写进代码，也不进 Git 仓库。**

原因：本产品最终要部署到 GitHub Pages 公开访问。任何写进前端代码的 Key 都会被任何人通过「查看源代码」看到并盗刷余额，浏览器里没有秘密可言。

当前方案：Key 与服务商配置一起存在使用者自己的浏览器 `localStorage` 里，代码仓库中零密钥，可一键清除。

后续若要公开发布让别人免 Key 体验，正确做法是加一层服务端代理（Cloudflare Worker 等）把 Key 挡在后端。这一步留到 v0.3。

## 五、技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 前端 | 原生 HTML / CSS / JS，无框架无构建 | 零安装门槛，双击即用，代码可读性高 |
| 接口 | OpenAI 兼容 `/chat/completions` | 事实标准，一家对接等于对接全部 |
| 默认模型 | DeepSeek `deepseek-v4-flash` | 便宜、中文强，但**可随时换** |
| 输出 | `response_format: json_object` + `temperature: 0` | 保证结构化、可复现；不支持时降级 |
| 部署 | 静态文件，GitHub Pages | 无需服务器 |

文件说明：

```
web/
├─ index.html       页面结构（练习 / 场景 / 测试案例 / 说明 四个页签）
├─ styles.css       样式
├─ providers.js     服务商预设 + Base URL 自动补全逻辑
├─ scenes.js        随机素材池：18 场景 × 10 性格 × 9 挑战 × 14 意外
├─ director.js      AI 导演：开局编剧本 + 剧本校验 + 失败回落
├─ scorecard.js     成绩卡 canvas 绘制
├─ app.js           逻辑：配置管理、提示词构造、API 调用、结构校验、批量测试
├─ testcases.js     20 条测试案例
├─ start.bat        本地启动脚本
└─ README.md        本文件
```

## 六、三个刻意的设计取舍

### 6.1 游戏化不等于徽章积分

没有做积分、等级、连续打卡、排行榜。这些是贴在表层的壳，很容易做成空壳。
这里的游戏化只做两件事：

1. **让纠错变成推进剧情的必要手段**——学习者需要它，而不是被它评判
2. **让每一局都不一样**——随机四张牌 + AI 现场编剧本，避免「玩两遍就背下来了」

「意外事件」是第 2 点的关键。它模拟真实交流里最让人慌的部分：
对方突然改口、你手机没电、旁边有人插话。这些情况课本上不教，
但恰恰是最需要练的——能不能在慌乱里把话说清楚。

### 6.2 AI 编剧本失败时必须说清楚

AI 导演返回的剧本要过 `validateScript()` 校验。不通过就用本地模板顶上，
并在页面和成绩卡上写明「本局剧本来自本地模板」。

不做「静默兜底」。用户以为自己在体验 AI 动态生成，实际拿到的是固定模板，
这跟伪造数据没有本质区别。

### 6.3 不美化成绩卡

成绩卡上如实显示「看了几次提示」「没说清几次」。用过的提示不会藏起来，
也不会给出一个虚高的分数让人开心。原因很简单——这个东西要拿去面试，
任何一个编造出来的数字，都会在追问里露馅。

评价规则完全公开，写在 `scorecard.js` 的 `rateRun()` 里：

| 没说清 | 看提示 | 评价 |
|---|---|---|
| 0 | 0 | 一遍过，表达很清楚 |
| 0 | >0 | 表达清楚，提示用得也克制 |
| 1-2 | 任意 | 基本能沟通，个别地方再打磨 |
| 3-5 | 任意 | 敢说就是进步，多练几轮会更顺 |
| >5 | 任意 | 先敢开口，准确度慢慢来 |

（`twistHandled` 为 true 时，「一遍过」会加一句「意外也接住了」）

## 七、提示词设计要点

系统提示词（`app.js` 的 `buildSystemPrompt`）做了这几件事：

1. **限定输出为纯 JSON**，且给出字段级结构说明，配合 `json_object` 模式双保险
2. **明确 `verdict` 四值枚举**：correct / minor / wrong / invalid
3. **「宁可放过，不可误判」**——句子正确时不许强行挑错。误判是这类产品最致命的缺陷
4. **只指出一个问题**，避免新手被一堆术语淹没
5. **解释难度随 HSK 等级变化**，且不出现专业语法术语
6. **禁止虚构**：不编造例句出处，不确定就说不确定
7. **异常输入必须返回 invalid**，不允许对纯数字/纯英文硬编语法问题

## 八、测试案例（20 条）

见 `testcases.js`，分四类：

| 类别 | 条数 | 检查什么 |
|---|---|---|
| 语法纠正 | 8 | 确实有问题的句子，能不能指出并改对 |
| 正确句 | 6 | 本来就对的句子，会不会被误判 |
| 等级适配 | 3 | 同一句在不同等级下解释难度是否有区别 |
| 异常输入 | 3 | 纯数字 / 纯英文 / 纯符号，会不会硬编答案 |

**自动化与人工的分工**：

- 工具自动检查：能否解析 JSON、字段是否齐全、`verdict` 取值是否合法、解释是否超长
- 必须人工核对：语义判得对不对。工具不自动计算「准确率」——那需要人来判断，自动编数字就是造假

批量运行后逐条在「人工评价」下拉框勾选，再导出 CSV，即测试报告的原始依据。

## 九、已知限制

- 无历史记录，刷新页面结果即消失
- 无用户系统，不保存学习进度
- 批量测试串行执行，20 条约需 1-2 分钟（取决于服务商）
- 只做单句纠错，不支持段落或多轮对话
- 未做流式输出，长句等待感明显
- 词库（小程序的 50 词）尚未接入网页版，AI 当前不参考具体词表
